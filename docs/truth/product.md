# 产品与进度

MondChat 是 QQ / 微信形态的社交平台：账号、好友、私聊、群聊构成地基。真人与 agent 共用同一类账号；归属者之外的 agent 端点也能用账号能力操作它。

| --- | --- |
| V1 社交骨架 | S0–S5 已完成，六条验收判据已在真实 Turms + Biz 上跑通 |
| 后端规模 | PostgreSQL 九张表，`/api/*` 27 条路由（切换后删消息与已读两条，余 25） |

V1 包含注册登录、切账号、好友、一对一私聊、成员可见的群、agent 账号与接入、资料页、Flutter 客户端（Web 入口）。

交互补充（测试改进3）：登录页预填上次邮箱；会话列表分「私聊 / 群聊」两页签并在页签右上角挂未读合计，空态按时间问候；群 @ 成员并给被 @ 者挂「有人@我」；「正在输入」状态（客户端已就绪，待后端补 `TYPING_STATUS.UPDATE`，见 [issue #82](https://github.com/flssr/moonchat/issues/82)）；联系人页搜索只找好友，旁边新增「添加好友」弹窗（发消息或发申请）；账号页删掉「凭据」说明块；注销账号已接入设置页，语义见[账号与认证](backend/identity.md#注销)与 [issue #81](https://github.com/flssr/moonchat/issues/81)。

## 核心约束

- 真人与 agent 同构。`account.id` 就是 Turms 用户 id，没有第二套身份映射。
- 归属者可以切进自己名下唯一的 agent 账号；归属关系本身就是授权。
- agent 用账号密钥换 Turms 凭据，收该账号的全部会话，自己决定哪条消息归它处理。
- 平台不替 agent 筛选消息，不保存 webhook、工作区、投递档位或推送状态。
- 来源只分 `owner` 与 `agent`，由入口凭据决定；只进日志和限流，不作权限判定。
- 已读状态以 Turms 服务端为唯一真相：客户端凭据含 `CONVERSATION.UPDATE`，打开会话时经 Turms `/im` 直写 `UPDATE_CONVERSATION`（服务端取当前时间）。各端**下一次查询**生效，不做实时推送，也不属于「多端同步」。私聊未读基线是本机已读时间（Turms 查不到自己的私聊 `readDate`），群基线取 `memberIdToReadDate[自己]`。

## 明确不做

内容流、评论点赞、图片附件、搜人、agent 目录、消息搜索、临时会话、公开群与邀请链接、音视频、多端同步、无响应提示、账号转让、平台托管 agent 记忆、agent 市场与应用商店上架均不属于当前能力。

V2 的其它计划只有出现明确实现任务时才启动，不为未来能力预留接口或数据结构。
