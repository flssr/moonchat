# MoonChat 客户端屏幕与状态 v1

- 日期：2026-11-11
- 对应页面：`frontend/preview/index.html`
- 对应规范：`DESIGN-SPEC.md`
- 接口依据：`docs/api-contracts.md`

## 1. 屏幕清单

| ID | 屏幕 | 入口 | 主要内容 | 主要动作 |
| --- | --- | --- | --- | --- |
| S1 | 登录 / 注册 | 未登录首屏 | 邮箱、密码、注册时的名字、错误行 | 登录、注册并登录、显示/隐藏密码 |
| S2 | 登录过渡 | S1 提交成功且拿到会话后 | 表单淡出、舱门关闭、朝月亮飞离 | 自动进入 S3 |
| S3 | 消息 | 登录后默认视图 | 会话列表（全部/私聊/群聊）、消息区、输入框、右栏信息 | 切会话、发消息、收起信息栏 |
| S4 | 群信息 | S3 右栏 | 群名、群主、成员、邀请、退群/移人 | 邀请、退群、移除成员、看成员资料 |
| S5 | 联系人 | 左侧导航“联系人” | 好友列表、待处理申请、添加好友、建群 | 同意/拒绝、加好友、发消息、建群 |
| S6 | 资料页 | 群成员、好友、添加好友的查找结果 | 名字、账号 ID、关系状态 | 加好友、同意/拒绝、发消息、删除好友 |
| S7 | 账号 | 左侧导航“账号”或会话列表底部账号行 | 我的真人账号与 agent、创建 agent、一次性密钥 | 切进账号、创建 agent、复制密钥 |
| S8 | 空状态 | 各列表无数据时 | 一句说明 + 可选动作 | 去联系人、创建 agent、返回 |

## 2. 视图与状态

```
view: "messages" | "contacts" | "account"
activeAccountId: number
activeConvKey: "dm:<peerAccountId>" | "room:<roomId>" | ""
convFilter: "all" | "dm" | "room"
friendsTab: "friends" | "pending"
selectedContact: account_id | null
profileId: account_id | null（资料抽屉）
```

约束：

- 私聊 key 是对端账号 ID，不是会话 ID；群聊 key 是 `room_id`。
- 切账号后，会话列表、好友、待处理、群成员关系都按新账号重算；当前会话若不属于新账号则回到第一条或空状态。
- 资料抽屉是覆盖层，不改变左侧选中项。
- 左栏折叠是展示状态，不持久化。

## 3. 流程

### 3.1 注册 / 登录

1. S1 默认登录；切“注册”只多出名字字段，不跳页。
2. 校验：邮箱含 `@`；密码 8–72 位且不能纯数字；注册名字 1–20 字。
3. 通过后：注册先调注册接口，再调登录；登录成功后拿登录 JWT，再用 `POST /api/sessions` 换 Turms 凭据。
4. 进入 S2：表单淡出 → 舱门关闭 → 朝月亮飞离，结束后进 S3。不做第二次确认，不需要再点门上的按钮。
5. 登录失败统一提示，不区分“账号不存在”和“密码错”。

### 3.2 切账号

1. S7 列出 `GET /api/accounts/mine`：自己第一，agent 按创建时间。
2. 点“切进” → `POST /api/sessions`（带登录 JWT 和 `account_id`）。
3. 拿到该账号的 `login_token` 与 Turms 凭据；重连 Turms，重算视图。
4. 新 agent 默认没有好友、没有群、没有会话，落在空状态。

### 3.3 加好友

1. 入口只有两个：群成员资料页、按账号 ID 查找。没有搜人。
2. 查 `GET /api/accounts/{id}`，显示名字、ID、`is_friend`。
3. 非好友：只有“加好友” → `POST /api/friendships`。
4. 收到申请：`GET /api/friendships?status=pending`，可同意/拒绝。
5. 同意后私聊入口立即出现（授权在写入网关现查 PG）。
6. 删除好友后会话保留、历史只读、输入框禁用。

### 3.4 私聊与群聊

1. 私聊只能从好友进入；群聊只能从自己已加入的群进入。
2. 发消息走 `POST /api/conversations/{dm|room}/{id}/messages`；本地先插入“发送中”，成功改时间，失败给重试。
3. 历史消息由客户端持 Turms 凭据直接查，按 `deliveryDate` 往回翻；Biz 不在读路径。
4. 没有已读回执、没有正在输入、没有附件、没有消息搜索。

### 3.5 群

1. 建群：S5 “建群”填群名，可选先拉一个人；创建者即群主。
2. 邀请：S4 成员区输入账号 ID，邀请即入群，不需要对方同意，也不要求是好友。
3. 退群：非群主可退；群主退群按钮禁用，V1 没有转让与解散。
4. 移除成员：只有群主能看到移除按钮；不能移除自己。

### 3.6 创建 agent

1. S7 只在当前是真人账号时提供“创建 agent 账号”。
2. 输入名字（≤20）→ `POST /api/agent-accounts`。
3. 201 响应里的 `account_key` 只展示一次；离开页面不保留明文。
4. 新 agent 是孤立账号：不入群、不加好友；要聊天得先建立关系。

## 4. 屏幕细节

### S1 登录 / 注册

- 表单与舞台左右分栏；窄屏上下排列。
- 错误贴在字段下方，字段描边变红，不弹窗。
- 舞台是「发射平台夜景」：夜空渐变、银河带、星点、整轮月亮、地平线与火箭三态；星点与银河不闪烁、不做视差；没有音效依赖。
- 夜空渐变只存在于舞台内，不进入表单或其他页面。
- 抵达后的样机里只给一张小会话卡，不在这里复制完整客户端。

### S2 登录过渡

- 只播一次，不能跳过；减少动态时直接到终态。
- 不做编号字幕、白光、整屏旋转或出画；离场只朝月亮收缩消失（机身转向月亮），整段约 1 秒。

### S3 消息

- 左栏：标题 + 新建按钮、三个筛选、会话行、底部当前账号。
- 中栏：会话头（头像、名字、身份/人数）、消息列表、输入框、发送按钮。
- 右栏：私聊资料卡或群信息；可收起。
- 会话为空：输入框可用，空状态提示“关系已经成立，发第一句话吧”。
- 群消息显示发送者名字；连续同人消息不重复头像。
- 发送中保留正文，时间位替换为“发送中…”。

### S4 群信息

- 成员行可点开资料页；群主行带“群主”标记。
- 邀请表单只接受数字账号 ID；失败在行内提示。
- 群主：退群按钮禁用并说明原因；可移除其他成员。
- 非群主：可退群；不能移除成员。

### S5 联系人

- “好友”与“待处理”两个标签，带数量。
- 待处理只显示发给我的申请；可同意或拒绝。
- 添加好友是账号 ID 查找，不是搜索框。
- 详情区默认给空状态，不默认选中任何人。
- “建群”与“添加好友”共用左侧列表区域，不新开页面。

### S6 资料页

- 只显示名字、账号 ID、关系状态；不显示邮箱、归属者、账号类型。
- 好友：发消息、删除好友（二次确认）。
- 非好友：只有加好友；已有申请：同意/拒绝；已发申请：显示已申请。
- 自己：只显示资料，无关系动作。

### S7 账号

- 账号行显示名字、账号 ID、类型（真人/agent）和当前标记。
- “切进”只在非当前账号上出现。
- 创建结果页展示完整密钥、复制按钮和“只显示一次”警告。
- 当前是 agent 时，创建入口替换为说明文字。

## 5. 空状态与错误

| 场景 | 页面文案 / 行为 |
| --- | --- |
| 账号无会话 | “这个账号还没有会话。先加好友，或被拉进群。” |
| 无好友 | “还没有好友。加好友需要对方的账号 ID 或主页链接。” |
| 无待处理 | “没有待处理的申请。” |
| 会话无消息 | “关系已经成立，发第一句话吧。” |
| 非好友会话只读 | “已不是好友：历史消息保留只读，不能再发新消息。” |
| 查找不到账号 | `not_found` → “这个账号不存在。” |
| 私聊被拒 | `not_friend` → 不显示输入框；资料页只留加好友 |
| 群被拒 | `not_room_member` → 回到会话列表并提示 |
| 限流 | `rate_limited` → 提示稍后再发，草稿保留 |
| 上游不可用 | `upstream_unavailable` → 消息标失败，给重试 |
| 凭据过期 | 静默刷新；刷新失败回登录页 |

## 6. 响应式

- ≤900px：左侧章节栏变顶栏，保留横向可滚动的章节。
- 容器 ≤860px：客户端样机收起右栏；群信息需要时再开。
- 容器 ≤620px：会话列表默认隐藏，用会话头的列表按钮打开；选中会话后回到消息区。
- 联系人、账号在窄屏上下排列，详情在列表下方。
- 390px 宽度下无横向溢出；图标按钮视觉 32×32，实现时补足 44×44 热区。

## 7. 演示与正式实现的差别

页面是前端状态样机，不连后端：

- 账号、好友、群、会话、消息都是页面内存里的种子数据，刷新复位。
- 登录、注册、建 agent 密钥不发起网络请求；密钥为本地生成。
- 只有 Luna 私聊有一条脚本化的自动回复，用来演示发送状态；正式实现由 Turms 推送。
- 切账号会重算本地视图，但不重放真实数据。
- 资料页、群信息、邀请、退群、移除、加好友、同意/拒绝都能点，状态只在本页生效。

正式实现必须替换为 `API-MAPPING.md` 里的请求，并保留同样的空状态与错误文案。

## 8. 已知缺口

- 客户端 spec 原缺，这份屏幕清单是补充，不是后端契约。
- 账号切换后会话列表如何重建，文档未规定；本页按“按账号重算”实现。
- 登录 JWT 7 天与 Turms 凭据 12 小时的续期提示位置未定；本页未画。
- 默认头像按账号 ID 生成，具体形态待定；本页用单字头像占位。
- 修改名字（`PATCH /api/accounts/me`）暂无界面入口。
- 通知、未读跨端同步、多端登录态不在本页范围。
