### 归属者与 agent 创建即好友

2026-11-15 11:31 CST   [2026-11-15 03:31 UTC]

决策：`POST /api/agent-accounts` 在创建事务内直接写 accepted 的 `friendship` 与镜像行，`requested_by` = 归属者；存量 agent 不回填。

原因：原设计靠前端串联四条接口（建 agent → 申请 → 切账号 → 同意），任一步失败都留下“建好但聊不了”的半成品，规则也只活在前端、其它调用方不会补；放进同一事务后对所有调用方成立，也不用替 agent 签发一次凭据去点同意。

### 黑名单

2026-11-14 15:02 CST   [2026-11-14 07:02 UTC]

决策：黑名单是有向关系，只拦“被拉黑方 → 拉黑方”的私聊与好友申请；不解除好友、不拦群聊、不投影 Turms，只有真人能操作。

原因：它解决一对一骚扰，不应改变群成员授权；所有写都经过 Biz，单点拦截不会留下客户端旁路。

### 并发重复写

2026-11-11 21:37 CST   [2026-11-11 13:37 UTC]

决策：好友申请与拉人保留先查后写，并用唯一键冲突兜底，落败方回 409。

原因：唯一键已经保证数据不脏；为毫秒级窗口引入 PG 方言 upsert 会破坏统一持久层写法。

### 好友双表

2026-11-04 20:42 CST   [2026-11-04 12:42 UTC]

决策：`friendship` 是授权真相，`friendship_reverse` 是同事务查询镜像；删除与拒绝写 tombstone，重新申请复用原行。

原因：按账号查询需要从两侧命中，但授权必须只有一个真相；墓碑保留后会话可以继续只读。

### 好友授权位置

2026-11-01 21:36 CST   [2026-11-01 13:36 UTC]

决策：好友不投影 Turms，私聊授权只在写入网关读取 PG。

原因：Turms 不需要知道好友；投影只会制造可漂移的副本和额外一致性窗口。
