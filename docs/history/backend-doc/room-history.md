### 成员事件按 PG 当前状态收敛

2026-11-26 02:35 CST   [2026-11-25 18:35 UTC]

决策：派发 `room_member.changed` 前读取当前 `room_member`，payload 的 `member` 与 `deleted_at is null` 不一致时直接标记处理；账号硬删后行不存在时仍允许 `member=false` 清理 Turms。整组投影成功后的唤醒时间留 1 秒余量，避免应用与 PG 容器时钟偏差导致事件短暂仍不可取。

原因：旧 `member=true` 可能在后续退群成功后被唤醒，把已退群账号重新加回 Turms；反向旧 `false` 会移除重新入群的账号。只按事件 id 唤醒无法保证目标状态仍有效，必须让 PG 当前成员状态成为最终判据。

### 群成员投影的幂等与句柄收敛

2026-11-26 01:44 CST   [2026-11-25 17:44 UTC]

决策：`TurmsAdminClient.addGroupMember` 只把 HTTP 409 且响应 `code=1103` 视为成员已存在的幂等成功；`ProjectionDispatcher` 派发成员事件时按 `room_id` 读取最新 `room_info.turms_group_id`；整组投影成功后把该群未处理成员事件的 `next_attempt_at` 唤醒为当前时间，不重置失败次数、不改写 payload。

原因：事务提交后的整组投影与 outbox 会重复写同一成员集合，Turms 唯一键冲突不能当上游故障；建群事件里的空句柄只是快照，回填后必须读 PG 当前值，否则事件会永久失败。仅唤醒而不查最新句柄、或仅查句柄而不唤醒，都无法让已退避到日级的存量事件及时收敛。

### 群消息路由

2026-11-11 20:34 CST   [2026-11-11 12:34 UTC]

决策：代发、历史与推送都使用 `turms_group_id` 映射，业务接口仍使用 `room_id`；句柄未回填时拒绝发送。

原因：Turms 只认自己的群 id；直接用业务 id 会串群，而且错误只会在投递侧暴露。

### 群真相归 PG

2026-11-04 20:44 CST   [2026-11-04 12:44 UTC]

决策：群、成员与账号侧群列表归 PG；Turms 仅保留投递必需的群与成员投影。

原因：授权与成员查询必须由业务层回答；Turms 的 group/member 可以按 PG 重建。

### 投影时序

2026-11-05 00:22 CST   [2026-11-04 16:22 UTC]

决策：`turms_group_id` 由 Turms 生成后回填；投影在事务提交后执行，失败不回滚业务写，`pending` 由最小重放器收敛。

原因：群业务真相在 PG，投影是可重建副产物；让副本失败回滚主数据会颠倒主从关系。
