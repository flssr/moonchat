### 重登恢复上次会话与本机缓存

2026-11-16 23:17 CET   [2026-11-16 22:17 UTC]

决策：Windows 桌面端把各会话最后 200 条、当前会话 key 和当前会话同步缓存到 `%APPDATA%\MondChat\cache.json`（按账号分，`MessageCacheStore` 注入），登录/恢复会话后先铺缓存再连 Turms；关闭应用时先同步落盘，然后直接 `exit(0)`，不再等 window manager 逐层 close。

原因：用户重开后会话列表只剩「私聊/群聊」、上次聊天也空了；Turms 只按打开的会话查历史，列表预览不会自己出现。缓存让首屏就是上次的内容，Turms 仍是最终真相。关闭慢是 Windows 插件回调链路在等，用户体感“点了没反应”；硬退前已经把缓存写完，不会丢最后一段。

### 消息提醒、社交反馈与关闭/托盘

2026-11-16 21:33 CET   [2026-11-16 20:33 UTC]

决策：按测试反馈补齐社交与桌面交互：加好友后按钮变「已申请」并在重新搜索时复位；被加方同意后由客户端自动发欢迎语；删掉空会话提示卡；资料页增加黑名单按钮；好友头像可开资料页；会话行显示最后一句话与未读角标；收到消息按设置弹桌面通知；关闭窗口先问「关闭应用程序 / 最小化到托盘」。桌面通知用 `local_notifier`，托盘用 `tray_manager` 0.5.x（0.8 走 nativeapi，本地 `flutter test` 需要 MSVC）。

原因：这些是客户端试用中暴露的反馈缺口，全部落在客户端；黑名单复用已有 `/api/blocklist`，不改消息唯一写入者与身份边界。自动欢迎语由同意方的客户端发送，对方离线时不会补发。

### 无边框窗口与铺满登录页

2026-11-16 17:47 CET   [2026-11-16 16:47 UTC]

决策：Windows 桌面端去掉系统标题栏（`window_manager` 的 `TitleBarStyle.hidden`），在 Flutter 里画 32px 自定义顶栏（拖动、双击最大化、最小化/最大化/关闭）；登录页用 `MondChatApp.edgeToEdge` 去掉居中卡片的外边距、描边与圆角，表单与舞台铺满客户区。Web 仍然用居中卡片。

原因：首版把网页的 1092×540 登录卡片直接塞进系统窗口，四周留白多，窗口又被标题栏和边框吃掉一块，看起来像缩小了。标题栏放在 `MaterialApp.builder` 里才能跟随应用自己的亮/暗色；铺满只在桌面开启，避免改掉 Web 已定的登录版式。

### Windows 桌面客户端

2026-11-16 17:16 CET   [2026-11-16 16:16 UTC]

决策：桌面端是 `desktop/` 下独立的 Flutter 工程，按路径依赖复用 `frontend/app` 的界面与状态，只实现 Windows 的本机文件存储（`%APPDATA%\MondChat`）与 Turms 读通道；exe 名为 `MondChat.exe`，由 CI 的 `desktop` job 在 `windows-latest` 上构建并上传 artifact。

原因：Flutter 的 Windows runner 必须与 `pubspec.yaml` 同目录，塞进共享包会把 `vendor/turms` 子模块拖进每次 Web CI；独立工程保住 Web 的检查面，也让桌面端只在自己需要时才拉固定提交的 Turms 依赖。开发机没有 Visual Studio 2022 的 C++ 桌面工作负载，无法本地出 exe，于是把构建放在 CI。

### 登录态持久化

2026-11-15 13:13 CET   [2026-11-15 12:13 UTC]

决策：登录成功后把归属者 JWT 与最后使用的账号 id 存进浏览器本地，刷新页面先用它换 Turms 凭据恢复会话；令牌失效时清掉副本回登录页。

原因：令牌之前只在内存里，刷新即丢，每次打开网页都要重登（issue #24）。Web 端没有 HttpOnly Cookie，要跨刷新保住登录只能依赖同源可读的本地存储，因此只放这一串 JWT，不放密码与 Turms 凭据。

### 关系列表轮询

2026-11-15 13:13 CET   [2026-11-15 12:13 UTC]

决策：登录后每 15 秒重拉好友、待处理与群三份列表，内容没有变化就不通知界面。

原因：好友与群没有推送通道（Biz 只校验不投递），别人发来的申请、别人建的群只能靠重拉才可见（issue #24）。只重拉这三份、不动资料与群详情缓存，避免已经打开的抽屉停在加载态。

### 导航状态

2026-11-11 19:34 CET   [2026-11-11 18:34 UTC]

决策：视图、会话和资料抽屉状态统一收进 `AppState`，页面只读状态，不再自行取数。

原因：多个页面各自维护导航会产生不可同步的状态副本；单一状态写入点更容易跨账号重置。

### Flutter Web

2026-11-10 22:00 CET   [2026-11-10 21:00 UTC]

决策：第一版客户端使用 Flutter Web，按 23 条 Biz 接口实现身份、关系、群与发言，读取通道单独接 Turms。

原因：一套代码可延伸到桌面与移动，网页链接也最适合加好友传播。
