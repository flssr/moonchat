### 联系人查找只找好友并加「添加好友」弹窗（测试改进3）

2026-11-24 23:42 CET   [2026-11-24 22:42 UTC]

决策：顶部搜索框占位改「搜索」，只在好友列表里按短号/完整 id 找；非好友不再打开资料页，右侧显示「未搜索到此好友」。「建群」旁新增「添加好友」弹窗：按 id 查人，不存在提示「未搜索到此好友」，已是好友给「发消息」直接开私聊，不是好友发申请，自己显示「这是你自己。」。

原因：`数据库/测试改进3.md` 第 8、9 条；原先点「查找」会把陌生人资料页当查找结果，且发好友申请没有独立入口。

### 切号与登出的页面状态收口

2026-11-24 23:20 CET   [2026-11-24 22:20 UTC]

决策：`_openSession` 开头清掉草稿、会话标题与黑名单缓存；消息/联系人/账号视图按账号 id 重建；「记住我」的选择记在 `AppState`，续期与切号沿用，不再把它们当成一次新的记住；登出时把根路由上的设置/黑名单/资料弹窗一并 pop；关系列表变更后清掉已不存在的选中会话。

原因：验收发现切号会把上一个账号的草稿带进新账号的输入框，取消记住我后切号又写回本机会话，以及窄屏在被移出群后停在空会话上。

### 记住我登录页补回登舱过渡

2026-11-17 13:28 CET   [2026-11-17 12:28 UTC]

决策：恢复本机会话和密码登录走同一条出口——`AppState.restore()` 只把会话恢复成 `ready`，登录页「记住我」卡片在成功后再播 800ms 登舱过渡（恢复期间按钮转忙碌，整屏留在登录页）；外壳删掉 `restored` 直达分支、恢复期间的启动页和 `AppState.restoring` / `restored` 两个字段。

原因：a43b525 取消启动自动 `restore()` 后，`restored` 直达与启动页只剩「记住我」这一条路在用，点登录会直接换到主界面，登舱动画看不到；启动页本来是为启动恢复防闪屏，现在反而成了点击后的闪屏。

### 登录页记住我

2026-11-17 01:20 CET   [2026-11-17 00:20 UTC]

决策：登录页加「记住我」（默认勾选）；勾选时把归属者 JWT、账号 id 和昵称存本机，下次打开登录页显示记住账号的昵称/头像，点「登录」恢复；取消勾选则登录后清掉本机副本。外壳启动不再自动 `restore()`，先停在登录页。`StoredSession` 增加 `displayName`。

原因：测试改进 2 的第 6 条；把是否记住交给用户，而不是无条件自动登录。

### 本机存储目录兜底

2026-11-17 00:37 CET   [2026-11-16 23:37 UTC]

决策：桌面端的设置/会话/消息缓存目录不再只认 `APPDATA`；依次试 `APPDATA`、`LOCALAPPDATA`、`USERPROFILE\AppData\Roaming`、exe 同目录，写一个探针文件确认可写后才用。

原因：用户机器上 `%APPDATA%\MondChat` 根本没建出来，会话/缓存/设置全是内存态，所以重开必重登、离线消息没有基线，角标和通知都不出现。用两个真实测试号跑“A 退出 → B 发 → A 重登”已验证逻辑本身正常（最后一条、未读 1、通知都有），问题在本机落盘目录。

### 会话置顶、未读角标与登录离线提示

2026-11-17 00:24 CET   [2026-11-16 23:24 UTC]

决策：会话列表按最后一条消息时间倒序，新消息会话置顶；单会话未读在行尾显示（99+），导航栏“消息”图标显示总未读。登录补拉到的离线未读不再因为“恢复的当前会话就是它”而跳过：照样累计未读并弹「N 条新消息 + 最后一条内容」的桌面通知；在线实时推送仍按“当前会话且窗口在前台”算已读。

原因：用户登录后只看到预览文字变化，没有数字角标和离线提示，会话也不按新消息排队。登录补拉的离线消息用户还没看过，必须提示；在线正看着的会话不打扰是保留的行为。

### 退出不再确认

2026-11-17 00:09 CET   [2026-11-16 23:09 UTC]

决策：删掉关闭确认弹窗（关闭应用程序/最小化到任务栏/取消）；标题栏关闭、Alt+F4/任务栏关闭和托盘「退出」都直接走 `_quit`，先同步落盘缓存再 `exit(0)`。标题栏的最小化按钮仍最小化到任务栏。

原因：用户明确不要这个弹窗，退出就是退出；托盘方案也放弃，不再需要“最小化到托盘”的确认分支。

### 托盘不可用，最小化改走任务栏

2026-11-17 00:00 CET   [2026-11-16 23:00 UTC]

决策：关闭确认里的「最小化到托盘」改为「最小化到任务栏」，直接 `windowManager.minimize()`，不再 `hide()`；托盘图标仍尝试创建，但不再作为恢复入口的依赖。离线通知等保持不变。

原因：Windows 11 上 `tray_manager` 0.5.x 的托盘图标不出现，`hide()` 后窗口和托盘都不可见，用户只能从任务管理器结束。任务栏最小化保留入口，进程继续收消息、弹通知；要真托盘需要换 nativeapi 版托盘插件，另行评估。

### 最小化到托盘的回退与离线通知

2026-11-16 23:52 CET   [2026-11-16 22:52 UTC]

决策：托盘未就绪/初始化失败时，「最小化到托盘」退化成任务栏最小化并弹一条说明，不再直接 `hide()`；托盘正常时隐藏窗口并提示已最小化到托盘。登录补拉发现的离线未读，除未读角标外也走和在线一样的桌面通知，正文是「N 条新消息 + 最后一条内容」。

原因：托盘图标没建好时 `hide()` 会让窗口和任务栏同时消失，用户体感就是“点了最小化结果应用被关了”；保留任务栏兜底就不会失联。离线消息只补角标不够，用户要的是和在线时同一种提示。

### 登录补拉会话预览与离线未读

2026-11-16 23:31 CET   [2026-11-16 22:31 UTC]

决策：登录/恢复会话并连上读通道后，对每个会话补拉最新一页（`_primeConversations`）：填列表最后一句，并把缓存基线之后的对端消息计入未读；缓存没有 `saved_at` 时用缓存里最新消息时间当基线。历史回填统一走 `_ingest(live: false)`，不累计未读、不弹通知；只有实时推送算“收到”。

原因：只靠本机缓存时，没打开过的群永远没有预览，离线期间的新消息也不会出现；Turms 的推送只覆盖在线时段。补拉把离线缺口补上，同时避免打开会话翻历史时被当成新消息刷未读/通知。

### 重登恢复上次会话与本机缓存

2026-11-16 23:17 CET   [2026-11-16 22:17 UTC]

决策：Windows 桌面端把各会话最后 200 条、当前会话 key 和当前会话同步缓存到 `%APPDATA%\MondChat\cache.json`（按账号分，`MessageCacheStore` 注入），登录/恢复会话后先铺缓存再连 Turms；关闭应用时先同步落盘，然后直接 `exit(0)`，不再等 window manager 逐层 close。

原因：用户重开后会话列表只剩「私聊/群聊」、上次聊天也空了；Turms 只按打开的会话查历史，列表预览不会自己出现。缓存让首屏就是上次的内容，Turms 仍是最终真相。关闭慢是 Windows 插件回调链路在等，用户体感“点了没反应”；硬退前已经把缓存写完，不会丢最后一段。

### 消息提醒、社交反馈与关闭/托盘

2026-11-16 21:33 CET   [2026-11-16 20:33 UTC]

决策：按测试反馈补齐社交与桌面交互：加好友后按钮变「已申请」并在重新搜索时复位；被加方同意后由客户端自动发欢迎语；删掉空会话提示卡；资料页增加黑名单按钮；好友头像可开资料页；会话行显示最后一句话与未读角标；收到消息按设置弹桌面通知；关闭窗口先问「关闭应用程序 / 最小化到托盘」。桌面通知用 `local_notifier`，托盘用 `tray_manager` 0.5.x（0.8 走 nativeapi，本地 `flutter test` 需要 MSVC）。

原因：这些是客户端试用中暴露的反馈缺口，全部落在客户端；黑名单复用已有 `/api/blocklist`，不改消息唯一写入者与身份边界。自动欢迎语由同意方的客户端发送，对方离线时不会补发。

### 无边框窗口与铺满登录页

2026-11-16 17:47 CET   [2026-11-16 16:47 UTC]

决策：Windows 桌面端去掉系统标题栏（`window_manager` 的 `TitleBarStyle.hidden`），在 Flutter 里画 32px 自定义顶栏（拖动、双击最大化、最小化/最大化/关闭）；登录页用 `MondChatApp.edgeToEdge` 去掉居中卡片的外边距、描边与圆角，表单与舞台铺满客户区。Web 仍然用居中卡片。

原因：首版把网页的 1092×540 登录卡片直接塞进系统窗口，四周留白多，窗口又被标题栏和边框吃掉一块，看起来像缩小了。标题栏放在 `MaterialApp.builder` 里才能跟随应用自己的亮/暗色；铺满只在桌面开启，避免改掉 Web 已定的登录版式。

### Windows 桌面客户端

2026-11-16 17:16 CET   [2026-11-16 16:16 UTC]

决策：桌面端是 `desktop/` 下独立的 Flutter 工程，按路径依赖复用 `frontend/app` 的界面与状态，只实现 Windows 的本机文件存储（`%APPDATA%\MondChat`）与 Turms 读通道；exe 名为 `MondChat.exe`，由 CI 的 `desktop` job 在 `windows-latest` 上构建并上传 artifact。

原因：Flutter 的 Windows runner 必须与 `pubspec.yaml` 同目录，塞进共享包会把 `vendor/turms` 子模块拖进每次 Web CI；独立工程保住 Web 的检查面，也让桌面端只在自己需要时才拉固定提交的 Turms 依赖。开发机没有 Visual Studio 2022 的 C++ 桌面工作负载，无法本地出 exe，于是把构建放在 CI。

### 登录态持久化

2026-11-15 13:13 CET   [2026-11-15 12:13 UTC]

决策：登录成功后把归属者 JWT 与最后使用的账号 id 存进浏览器本地，刷新页面先用它换 Turms 凭据恢复会话；令牌失效时清掉副本回登录页。

原因：令牌之前只在内存里，刷新即丢，每次打开网页都要重登（issue #24）。Web 端没有 HttpOnly Cookie，要跨刷新保住登录只能依赖同源可读的本地存储，因此只放这一串 JWT，不放密码与 Turms 凭据。

### 关系列表轮询

2026-11-15 13:13 CET   [2026-11-15 12:13 UTC]

决策：登录后每 15 秒重拉好友、待处理与群三份列表，内容没有变化就不通知界面。

原因：好友与群没有推送通道（Biz 只校验不投递），别人发来的申请、别人建的群只能靠重拉才可见（issue #24）。只重拉这三份、不动资料与群详情缓存，避免已经打开的抽屉停在加载态。

### 导航状态

2026-11-11 19:34 CET   [2026-11-11 18:34 UTC]

决策：视图、会话和资料抽屉状态统一收进 `AppState`，页面只读状态，不再自行取数。

原因：多个页面各自维护导航会产生不可同步的状态副本；单一状态写入点更容易跨账号重置。

2026-11-10 22:00 CET   [2026-11-10 21:00 UTC]

决策：第一版客户端使用 Flutter Web，按 23 条 Biz 接口实现身份、关系、群与发言，读取通道单独接 Turms。

原因：一套代码可延伸到桌面与移动，网页链接也最适合加好友传播。
