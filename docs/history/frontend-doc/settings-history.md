### 新建 agent 即归属者好友

2026-11-23 21:48 CET   [2026-11-23 20:48 UTC]

决策：`AppState.createAgent` 创建成功后除了重拉 `GET /api/accounts/mine`，再调用 `refreshRelations()` 立刻刷新好友/群列表；账号页文案改成「新建 agent 会自动和你的真人账号成为好友；它不入群，要进群需手动拉入」。

原因：后端建 agent 的同一事务里已写入归属者与 agent 的 `accepted` 好友关系（docs/truth/backend/friendship.md）；客户端原来的「孤立账号、不加好友」文案和等 15 秒轮询都是旧行为，创建完看不到 agent 好友会造成「建了但没生效」的错觉。

### 新建 agent 的默认头像

2026-11-17 17:07 CET   [2026-11-17 16:07 UTC]

决策：`AppState.createAgent` 在拿到新账号 id 后，按 `account_id % 3` 从三张 agent 默认头像里挑一枚，用和资料编辑同一个 `setAvatar` 落本机偏好；不新增服务端字段。

原因：创建流程原来不给头像，新建 agent 在账号列表、资料页和会话里全是按 id 生成的首字头像，看起来像「创建时头像没保存」。服务端头像列还是 issue #10，先在客户端补上默认值；#10 落地后这行改成写服务端即可。

### 资料编辑

2026-11-14 17:21 CET   [2026-11-14 16:21 UTC]

决策：资料编辑改用 `GET /api/accounts/me` 回填、`PUT /api/accounts/me` 全量提交；打开时先加载完整资料，加载失败停在错误态并给重试，不拿登录或 `mine` 里的列表字段假装资料。

原因：后端把资料写入从 `PATCH` 改成 `PUT` 并新增了读接口；登录、切账号与 `mine` 只回鉴权与列表字段，继续拿它们回填会把性别读成默认值，保存时覆盖掉真实的生日。

2026-11-12 18:52 CET   [2026-11-12 17:52 UTC]

决策：头像入口打开资料编辑器，加入性别、生日与星座联动；保存先复现后端已存在的资料回显边界。

原因：界面先行收口个人信息体验；后端尚未实现这些字段，因此当前保存失败是明确缺口。

### 头像改由服务端存

2026-11-17 17:19 CET   [2026-11-17 16:19 UTC]

决策：头像不再以本机选择为准——资料编辑里点一枚就调 `PUT /api/accounts/me/avatar`（`null` 清回首字头像），客户端只把服务端 payload 里的 `avatar` 缓存进本机渲染（`mondchat.avatars.v1`），登录、`mine`、好友、群成员、资料页、资料保存都按回显刷新缓存；新建 agent 的默认头像改由服务端分配。

原因：issue #10 落地后服务端才是真相，本机偏好只在自己这台机器上可见；缓存只服务渲染与离线，不再产生冲突。原来创建 agent 由客户端落默认头像的那行随之删掉，避免和服务端回显打架。

### 头像

2026-11-14 12:45 CET   [2026-11-14 11:45 UTC]

决策：资料编辑里提供平台默认头像选择：真人 6 张、agent 3 张，选中即生效；按 `account_id` 存在本机 `localStorage`（`moonchat.avatars.v1`，与设置分开），不做上传。

原因：服务端还没有头像列，先用同一套默认头像让客户端可用；服务端存 key 之后，前端把「本机优先」改成「服务端优先」即可。

### 本地设置

2026-11-12 21:06 CET   [2026-11-12 20:06 UTC]

决策：字体、语言和主题保存在浏览器本地，并对非法值回默认。

原因：这些是设备偏好，不需要进入账号业务真相；本地存储只信任三档字号、四门语言和三种主题。

### 多语言

2026-11-12 20:55 CET   [2026-11-12 19:55 UTC]

决策：主要界面文案支持中文、英文、日文与德文，用户内容不翻译。

原因：界面语言随本地偏好立即切换；账号名与消息正文是用户数据。
