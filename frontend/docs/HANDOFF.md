## 3. 还原必须对齐

### 颜色与主题

- 严格使用 `DESIGN-SPEC.md` 第 2 节的 token；不要在组件里写死十六进制。
- 亮色与暗色是同一套结构，只换值；切换不得改变布局、字号或间距。
- 主按钮用墨色；月壤红只出现在未读、焦点环、错误、删除。
- 自己的消息是 `--surface-2` 底 + 1px 描边，不是实心墨。

### 字体与排版

- 系统字体栈，不加载网络字体；标题 400 字重，靠字号建立层级。
- 中文不追字距；账号 ID、时间、密钥用等宽字。
- 章节留白与页面留白按规范第 4、5 节；不要加营销页式的居中大标题。

### 布局

- 客户端样机：56 / 252 / 自适应 / 236，高 620；容器 ≤860 收右栏，≤620 收会话栏。
- 登录：44 / 56，min-height 540；窄屏上下排列。
- 联系人/账号：320 + 自适应；窄屏上下。
- 资料页：右侧抽屉，宽 min(352, 88%)。
- 390 宽不得出现横向滚动。

### 组件状态

按 `DESIGN-SPEC.md` 第 6 节逐项核对：

- 按钮：主要、次要、文字、危险、小号、禁用。
- 输入：默认、悬停、焦点、错误。焦点样例必须使用 `.field.is-focus`，不能只填值。
- 气泡：对方、自己、发送中、失败；发送中保留正文。
- 标记：好友、群主、待处理、未读数字、账号 ID、一次性密钥。
- 空状态：无会话、无好友、无待处理、无消息、只读会话。
- 图标按钮视觉 32×32；实现时补足到 40×40 热区（移动端 44×44）。

### 交互时序

| 场景 | 时长 | 缓动 |
| --- | --- | --- |
| 悬停、按下、发送状态 | 120ms | `.2,.7,.2,1` |
| 主题、弹层 | 200ms | 同上 |
| 会话切换、资料页 | 320ms | 同上 |
| 登录表单收束 | 420ms | 同上 |
| 舱门 | 180ms | 同上 |
| 离地 | 620ms | `.16,1,.3,1` |
| 抵达 | 200ms | 同上 |

- 不做编号字幕、白光、旋转、飞出画面、滚动淡入、回弹、无限循环动画。
- 减少动态：直接到终态，保留可读性。

### 接口

- 读：客户端持 Turms 凭据直接查会话与历史，按 `deliveryDate` 分页；Biz 不在读路径。
- 写：只有 `POST /api/conversations/{type}/{id}/messages`；客户端 Turms 凭据只授 `QUERY`。
- 不做已读回执、正在输入、消息搜索、附件、音视频。
- 资料页只显示名字、账号 ID、是否好友；不显示 agent 类型与邮箱。
- 群主判断用 `account_id == owner_account_id`；成员列表没有 role 字段。
- 邀请即入群；群主不能退群；移除成员只有群主能做。
- 新 agent 创建后是孤立账号：不入群、不加好友。

## 4. 状态模型

```
LoginPhase: idle → launching → arrived
AppView: messages | contacts | account
MessageState: sending | sent | failed
Relation: self | friend | incoming | outgoing | none
```

实现建议保留同样的状态枚举，不要用多个布尔量拼状态。

登录进入后必须先完成：

1. `POST /api/auth/login` 拿登录 JWT。
2. `POST /api/sessions` 拿 Turms 凭据与网关地址。
3. 连 Turms，拉会话与历史；再拉 `accounts/mine`、好友、群列表。
4. 播完登舱过渡再切主界面；正式客户端由登录页的 `onArrived` 交给外壳，登录态本身不塞动画时长。

## 5. 验收清单

在 1440 与 390、明暗两套下逐条过：

- [ ] 登录：错误提示、密码显隐、关门、短促离地、抵达、重播；减少动态下直接进入。
- [ ] 注册：多出名字字段、校验、注册成功后再登录。
- [ ] 消息：全部/私聊/群聊筛选、切会话、未读清零、发送中到已发送、失败重试。
- [ ] 非好友：资料页没有发消息；删除好友后会话只读。
- [ ] 群：建群、邀请、退群、群主不能退、群主移人。
- [ ] 账号：切进、当前标记、新 agent 空状态、创建密钥只显示一次。
- [ ] 明暗切换无布局跳动；对比度达标；月相与地平线可见。
- [ ] 键盘可走完主要流程；焦点可见；Esc 关闭资料页/侧栏。
- [ ] 减少动态下流程仍可完成。
- [ ] 390 宽无横向溢出；会话列表按钮可用。
- [ ] 无已读回执、无正在输入、无消息搜索、无附件入口。

## 6. 已知边界

- 页面是状态样机，不连后端；数据刷新即复位。
- 登录、注册、建 agent、切账号、发消息都不发真实请求。
- 只有 Luna 私聊有一条脚本化自动回复，用于演示发送状态。
- 密钥是本地生成；真实接口返回 UUIDv4，且只出现一次。
- 基线截图只用于评审说明，不进入正式产品。
- 客户端 spec 原缺；这三份文档补的是界面与接口映射，不替代后端 spec。
- 账号切换后的列表重建、默认头像形态、凭据续期提示位置仍是未定项。

## 7. 文档与页面对照

1. `DESIGN-SPEC.md` 的颜色 token、字号、间距、圆角、动效时长是否与 `preview/styles.css` 一致。

3. `API-MAPPING.md` 的路径、字段、错误码是否与 `docs/api-contracts.md` 一致。
4. `SCREEN-MAP.md` 的屏幕清单与入口是否与 04 节样机一致。

页面改动时，先改 `preview/`，再同步本文档；不要把文档写成第二套设计。
